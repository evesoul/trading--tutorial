# 多指标共振

本文件是教学框架，不是教程正文，也不是交易信号。

**核心命题：指标越多，并不等于判断越准确。**

先修：本目录下其余组合课。本课收束 Part 2，并通向 Part 3 的交易系统。

## 教学目的

1. 共振的正当含义：几个回答 **不同问题** 的观察指向同一上下文。
2. 共振的滥用：把几个回答 **同一问题** 的指标叠在一起，当成独立证据。
3. 给学习者一套“指标分工表”，而不是一张越来越长的买入清单。
4. 说明冲突时怎么处理：等待、空仓或回到更高一层的环境判断，而不是加第 6 个指标投票。

## 什么叫共振，什么不叫

共振（教学定义）：

> 在已经识别的市场环境里，方向、力度、参与度或拥挤程度等 **不同维度** 的观察没有互相否定。

不叫共振：

- RSI、MACD、KDJ 同时金叉
- 5、10、20、60 周期均线全部多头排列就当作四重确认
- 把同一根 EMA 的斜率、MACD 零轴、价格新高数三遍

后一类只是同一份价格信息的重复采样。重复采样不能降低未来的不确定性，却容易提高主观信心，从而加大杠杆。这是本课要拆穿的机制。

## 每个指标只占一个问题槽

设计组合或系统时，先填问题，再选指标。一个问题槽只留一个代表。

| 问题槽 | 要回答的问题 | 可选代表（择一） | 常见重复项（不要再堆） |
|---|---|---|---|
| 环境 / 方向 | 现在更像趋势还是震荡，偏向哪一侧 | 价格结构，或一条/一组 EMA | 再加 MA、再加一条同向 MACD 当趋势 |
| 力度 | 涨跌是在加强还是减弱，是否过快 | RSI **或** MACD | RSI + MACD + KDJ |
| 参与度（流量） | 成交是否相对活跃 | Volume | 多交易所混加的总量、未解释的 CVD |
| 仓位存量 | 未平仓在增还是在减 | OI | 把 OI 再解释成方向指标 |
| 拥挤与持有成本 | 谁在为持仓付费，存量大不大 | Funding，并与 OI 对照 | 把费率当反向计时器 |
| 风险与执行 | 亏得起多少，错了在哪退 | 止损、仓位、禁止条件 | 任何指标都代替不了这一槽 |

表里“可选代表”不是推荐参数，是分工示例。Knowledge 尚未完成的指标，不在本框架里发明新公式。

## 最小可用的观察栈

教学上建议的上限：

1. 一个环境/方向工具
2. 一个力度工具（可空）
3. 一个参与度或存量工具（可空）
4. 风险规则（必有，且不是指标）

例如：EMA + RSI + Volume，再加止损与单笔风险。  
例如：价格结构 + OI + Funding 过滤，再加止损与单笔风险。

不建议：EMA + MA + MACD + RSI + KDJ + 布林带 + Volume + OI + Funding 全部亮绿灯才开仓。条件看起来很严，实际要么几乎没有样本，要么只是在拟合一段历史。

## 共振时怎么处理

共振只说明：“当前画面比较清楚，可以进入是否存在交易前提的讨论。”

它不说明：

- 入场价已经出现
- 胜率更高
- 可以放大仓位或提高杠杆
- 可以省略止损

正确落入链路的方式：

```
环境清楚
→ 方向规则给出偏向
→ 不同问题槽没有互相否定（共振）
→ 这只是 Setup 可能成立
→ 仍要等 Entry
→ 仍要先写 Stop Loss
→ 再算 Position Size
```

若发现自己因为共振就想“多开一点”，这是仓位纪律问题，不是指标问题。见 [position-sizing.md](../position-sizing.md)。

## 冲突时怎么处理

冲突指：两个 **不同问题槽** 给出难以同时成立的画面，或同一槽内部的代表互相打架。

处理顺序：

1. 先问是不是同一槽在重复。同一槽冲突，删到只留一个代表。
2. 不同槽冲突（例如方向仍上、参与度明显变弱、拥挤已经极端）：Setup 不成立，默认等待或空仓。
3. 不要引入第三个同类指标来投票。
4. 已经持仓时，冲突用来检查离场规则是否被触发，而不是即兴反手。

| 冲突例子 | 槽 | 处理 |
|---|---|---|
| EMA 向上，RSI 与 MACD 一个强一个弱 | 力度槽内部重复 | 只保留一个力度工具 |
| EMA 向上，成交量递减，OI 下降 | 方向 vs 参与/存量 | 不把上行当成加速前提 |
| 价格创新高，费率极端且 OI 很高 | 方向 vs 拥挤风险 | 降低风险预算或禁止追单，不是自动开空 |
| 短周期动量向上，长周期结构向下 | 周期未对齐 | 先统一决策周期，再谈组合 |

## 适用环境

- 学习者已经分别上过趋势动量、量价、OI、资金费课程。
- 用来写自己的观察清单，或填写 [system-template.md](../system-template.md) 的第 4–6 节。
- 用来审查“我是不是把同一问题问了四遍”。

## 失效环境

- 把共振当成胜率放大器。
- 在数据质量差、流动性差、清算进行中仍要求所有格子对齐。那种时刻更该触发禁止交易条件。
- 为每一种冲突发明一个新指标去修补。修补应发生在规则写清楚之后，并通过回测检查，而不是加图层。

## 放入交易系统的位置

多指标观察只覆盖链路前半：

`Market Regime → Direction → Setup → Entry`

后半必须离开指标层：

`Stop Loss → Take Profit → Position Size → Exit → Review`

Part 3 的完整案例可以引用本课的问题槽表，但案例是“如何写系统”的样本，不是推荐实盘组合。

## 常见误区

1. **指标越多越准确。** 本课的直接反例。相关指标增加的是信心，不见得会增加新信息。
2. **全部对齐才做，所以很安全。** 过滤过严会剩很少交易；很少交易的漂亮成绩更容易是运气。风险也不会因为过滤变严而变成零。
3. **多数指标同意就可以加大杠杆。** 杠杆放大的是亏损速度。永续有爆仓。
4. **冲突说明市场要变盘，应该提前反手。** 冲突首先是“现在不清晰”。
5. **回测里不断加入能提高历史曲线的新指标。** 这是拟合，见 [backtest.md](../backtest.md)。
6. **没有指标的结构规则不算系统。** 相反，清晰的价格结构可以单独占方向槽。

## 风险

- 确认偏差：只看见对齐的格子，看不见没对齐的。
- 过拟合：历史图上能对齐的条件，换一段行情就消失。
- 执行瘫痪：格子太多，学习者无法在盘中按同一规则复述。
- 爆仓：信心上升快于风控规则落地。
- 把教育内容误当成信号源：本项目任何组合页都不能写成可执行喊单。

## 给 Content Agent

- 标题和导语必须出现这句意思：**不是指标越多越准确。**
- 建议课堂活动：发给一张堆满指标的图，让学习者删到最多三个问题槽。
- 用一张“问题槽表”贯穿全文，不要用“七重共振战法”时间线。
- 正案例：三个不同槽一致，但仍写止损，且说明后来仍可能失败。
- 反案例：五个动量指标一致后价格继续震荡，或一致后出现反向清算。
- 结束时把学习者送到系统模板，而不是送到下一组更复杂的指标。
- 需要 Visual：问题槽示意图、重复采样示意图、过严过滤导致样本过少的示意图。不要用虚构权益曲线证明“三个指标的组合更赚钱”。

## 给 Visual Agent 的图需求

- 问题槽表的信息图（示意图）
- 同一段行情：三动量重叠 vs 方向+力度+成交量分工
- “对齐后仍失败”的真实行情（完整元数据）
- 明确禁止：用累计收益柱状图比较“指标数量”与“收益”
