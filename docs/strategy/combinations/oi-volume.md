# 持仓量 + 成交量（OI + Volume）

本文件是教学框架，不是教程正文，也不是交易信号。

先修：[price-oi.md](./price-oi.md)、[trend-volume.md](./trend-volume.md)。本组合把“存量”和“流量”放在一起，仍把价格留在上下文里。没有价格，OI 与成交量无法讨论方向。

## 教学目的

1. 成交量是一段时间里成交了多少，OI 是现在还挂着多少未平仓合约。
2. 放量加仓、放量减仓、缩量加仓是三种不同过程，含义不同。
3. 本组合帮助描述“仓位是怎样变化的”，不帮助预测突破方向。
4. 高成交、高 OI 同时出现时，流动性与清算风险都可能上升，教学要落到风险，而不是“机会更大”。

## 各指标回答什么问题

| 观察对象 | 主要回答 | 不负责回答 |
|---|---|---|
| Volume | 这一段成交有多活跃（流量） | 这些成交是开仓还是平仓 |
| OI | 未平仓合约变多还是变少（存量） | 成交有多热、谁在主导 |
| Price（上下文） | 上述变化发生在涨、跌还是横盘里 | 单靠价格分不清加仓还是减仓 |

合在一起，才能讨论下面这句完整观察：

> 在这段价格运动里，市场是在用很多成交把仓位做大，还是用很多成交把仓位拆掉，或只是在原仓位上频繁换手。

## 观察框架

先固定同一合约、同一时间窗口，再比较成交量相对近期是否放大，以及 OI 是升、降还是几乎不变。

| Volume | OI | 教学读法 | 不能推出的结论 |
|---|---|---|---|
| 放大 | 上升 | 活跃成交伴随仓位扩张，更像开仓过程占主导 | 下一步继续按现价方向走 |
| 放大 | 下降 | 活跃成交伴随仓位收缩，更像平仓、回补或清算 | 涨跌即将结束或反转 |
| 放大 | 几乎不变 | 换手高，净仓位变化小 | “主力在吸筹”或“即将突破” |
| 缩小 | 上升 | 较少成交里仓位仍在增加，可能是缓慢开仓，也可能是数据滞后 | 隐蔽而可靠的趋势 |
| 缩小 | 下降 | 市场在安静地减仓或兴趣下降 | 马上低波动或马上反转 |
| 缩小 | 几乎不变 | 参与度和存量都没有明显变化 | 可以忽略风险 |

每一行都必须带回价格：同样是“放量 + OI 下降”，发生在急涨后的滞涨，和发生在急跌后的反弹，故事不同。

## 共振

对本组合，共振指：流量和存量指向同一种过程，且与价格结构不互相否定。

- 价格沿趋势推进，成交放大，OI 上升：推进伴随开仓。这是最常被拿来当“趋势健康”的画面，但仍会失败。
- 价格剧烈波动，成交放大，OI 下降：仓位在被拆除。可能是趋势中的清洗，也可能是行情结束段。教学只描述过程。
- 区间内成交放大而 OI 几乎不变：更像在原有仓位上换手，不宜当成方向确认。

## 冲突

| 冲突 | 可能的读法 | 教学处理 |
|---|---|---|
| 价格突破，成交放大，OI 下降 | 突破由平仓推动 | 不把这次突破写成“趋势启动前提” |
| 价格平静，OI 快速上升，成交并不大 | 存量增加但流量低 | 检查数据延迟；不要解释成聪明钱静默布局 |
| 成交量脉冲很高，OI 更新几乎不动 | 流量与存量时间错位 | 先怀疑更新频率，再做解释 |
| 价格、成交量、OI 同时无序跳动 | 清算或数据问题 | 进入禁止交易讨论，而不是找形态 |

冲突时默认：降低解释力度，回到价格结构；必要时空仓。不要用成交量去“修正”OI，或反过来。

## 适用环境

- OI 与成交量来自同一交易所的同一永续合约。
- 更新频率与教学内容的周期匹配，例如用 1H 或 4H 讨论仓位过程，而不是用 1 分钟噪声。
- 学习者已经能先说出价格在趋势还是区间。

## 失效环境

- 全网成交量配单一交易所 OI，或相反。
- 活动拉量、自我成交、指数成分调整造成量能失真。
- 只在事件当天看一张图，没有“事件前的正常量与正常 OI 变化”作参照。
- 把 CVD、主动买入量与成交量、OI 画在一起，却不说明各自问题，造成“三个指标都确认了”的错觉。

## 放入交易系统的位置

| 链路步骤 | 可以提供的观察 | 不能代替 |
|---|---|---|
| Market Regime | 当前是加仓市、减仓市还是换手市 | 趋势/震荡的价格定义 |
| Direction | 不提供方向 | 价格与趋势规则 |
| Setup | 过滤：例如“平仓推动的突破，不作为趋势跟踪前提” | 入场价 |
| Entry | 不建议单独触发 | 若使用，必须写成可复算的量能与 OI 变化阈值 |
| Stop Loss 及之后 | 提醒：高量高 OI 时滑点可能变差 | 具体止损算法 |

与 [price-oi.md](./price-oi.md) 的分工：Price + OI 先建立四象限语言；本课加入流量，区分开仓主导还是平仓主导。不要两课写成两套互相矛盾的口诀。

## 常见误区

1. **放量又加仓 = 可以加大杠杆。** 仓位扩张时，反向波动的清算风险也在上升。
2. **放量减仓 = 见顶或见底。** 减仓可以发生在中途换防。
3. **OI 不变的放量没有意义。** 它可能正是区间争夺或对倒，值得当“方向不明确”的证据。
4. **用一根天量、一个 OI 拐点做决策。** 过程要用一段变化来描述。
5. **以为看懂存量流量就不需要止损。** 清算发生时，解释往往落后于价格。

## 风险

- 永续合约在 OI 高、成交突然放大时，容易出现连续强平和滑点扩大。教学应导向“减小仓位或暂停”，而不是“抓住机会”。
- 把过滤条件写得过细（同时要求放量、OI 升、价格新高），样本会变少，回测更容易过拟合。
- 数据不同步会造成虚假共振。
- 本组合看不到持有成本。仓位很大且资金费率极端时，见下一课。

## 给 Content Agent

- 用“河里的流量 vs 水库里的水量”类比流量和存量。
- 至少三个对照案例：放量加仓、放量减仓、放量但 OI 不变。
- 每个案例先写价格，再写量和 OI，最后写“我不能据此开仓的原因”。
- 禁止把表格单元格写成“开多/开空”。
- 需要时申请 Visual：三组对照图 + 一张清算过程时间轴（示意图）。

## 给 Visual Agent 的图需求

- 同一段趋势上标注成交量柱与 OI 曲线
- 放量 + OI 下降的平仓推动突破
- 放量 + OI 平坦的区间换手
- 明确标注示意图或真实行情元数据
