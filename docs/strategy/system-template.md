# 交易系统设计模板

本模板用来把一套交易想法写成可检查的规则。它是作业纸，不是已经验证过的策略，也不提供交易信号。

填写时遵守逻辑顺序：

```
Market Regime → Direction → Setup → Entry → Stop Loss → Take Profit → Position Size → Exit → Review
```

升级后的观察链路还包含多周期、订单、成本、热度、执行偏差。它们写进下面各节的**填写说明**，**不新增 1–12 编号**。完整链路见 [README.md](./README.md)。

与下面 12 节的对应关系：

| 逻辑步骤 | 模板章节 | 填写时先想清楚的问题 |
|---|---|---|
| Market Regime | 4. 市场环境 | 现在允许交易的环境是什么？其他环境是否空仓？ |
| Direction | 5. 方向判断 | 偏多、偏空还是不做，规则是什么？ |
| Setup | 6. 入场条件中的前提部分 | 哪些条件只说明“可以开始找触发”？ |
| Entry | 6. 入场条件中的触发部分 | 哪一条发生后才执行？ |
| Stop Loss | 7. 止损 | 错了在哪里退出？这一步必须先于仓位。 |
| Take Profit | 8. 止盈 | 对了如何减仓或全平？ |
| Position Size | 9. 仓位 | 单笔最多亏账户的多少？ |
| Exit | 7、8，以及 10 中的强制离场 | 还有没有时间离场、规则失效离场？ |
| Review | 12. 复盘 | 有没有遵守规则？ |

填写说明里还要能落到这些位置（仍不新增编号）：

| 补充主题 | 写进哪一节 | 框架文件 |
|---|---|---|
| 决策周期 / 执行周期 | 3，并约束 4、5 | [multi-timeframe.md](./multi-timeframe.md) |
| 订单类型与未成交怎么算 | 6、7 | [execution.md](./execution.md) |
| 成本对照 R | 9、11 | [cost-vs-r.md](./cost-vs-r.md) |
| 账户热度与相关品种 | 9 | [risk-management.md](./risk-management.md) |
| 事件 / 周末 / 连续强平 / 执行偏差 | 10，复盘进 12 | [risk-management.md](./risk-management.md) |
| 样本外、滚动前进 | 11 | [backtest.md](./backtest.md) |

指标组合只进入第 4–6 节的观察层。止损、仓位、回测、复盘不由指标“自动给出”。

以下 12 节结构保持不变。每节后的“填写说明”是教学补充，不是新的编号章节。

## 1. 系统名称

填写系统名称。

填写说明：用“市场 + 周期 + 核心观察”命名，便于复盘检索。例如“BTCUSDT-4H-趋势回调观察”。名称不要写成收益承诺。

## 2. 交易市场

例如 BTCUSDT、ETHUSDT。

填写说明：写清合约类型（U 本位永续）、交易所或数据源、是否只做主流品种。不同品种的流动性、滑点、资金费率差异会改变同一套规则的表现。不要默认“所有币都能套用同一套参数”。

## 3. 时间周期

例如 15m、1H、4H。

填写说明：写清**决策周期**和**执行周期**，并且事先写死。例如用 4H 判断环境与方向，用 15m 只找触发。两周期打架时默认不交易或等对齐，禁止切到「更能讲通」的周期。未收盘的低周期不能推翻已收盘的高周期。周期越短，噪声和交易成本占比通常越高。回测与实盘观察应使用同一周期定义。详见 [multi-timeframe.md](./multi-timeframe.md)。本模板不把多周期扩成第三层编号。

## 4. 市场环境

趋势 / 震荡 / 高波动 / 低波动。

填写说明：这是链路的第一步。至少写清：

- 用什么观察区分环境（结构、波动幅度、均线斜率等）
- 每种环境是否允许开仓
- 环境识别失败时是否默认空仓

同一组 EMA、RSI、成交量在趋势和震荡里含义不同。环境规则含糊时，后面的入场条件无法稳定执行。

## 5. 方向判断

必须规则化。

填写说明：方向是“偏多 / 偏空 / 空仓”，不是“现在去下单”。规则要能让两个执行者得到同一结论。避免“看起来要涨”这类主观句。方向未确立时，不进入交易前提。

## 6. 入场条件

明确条件1 + 条件2 + 条件3。

填写说明：把条件拆成两层，不要混在一句里。

- **交易前提（Setup）**：环境 + 方向 + 结构位置已经满足。
- **入场触发（Entry）**：例如收盘确认、回踩后再次离开某条均线、成交量放大到某个可检查的标准。

建议写成“必须同时满足”或“满足 A 后等待 B”，并写清“只满足一部分时不做”。条件来自指标组合时，每个条件应能对应到“它回答什么问题”，避免三个条件其实在问同一件事。

触发之后还要写**订单与成交**，否则第 11 节会暗含「每个信号都完全成交」：

- 开仓用市价还是限价；是否只做 maker；有效期（GTC / IOC / FOK 用白话即可）
- 未成交、部分成交事先选定一种算法：视为未入场，或按已成交部分重算仓位与热度
- 允许追价的话，追几次、最差到哪、超过则未入场，也要写死；未写则视为未入场

详见 [execution.md](./execution.md)。不要把订单写成交易所按钮教程。

教学示例（只说明如何写规则，不是推荐策略）：

1. 环境：4H 收盘位于慢速 EMA 之上，且近期摆动高点高于前高。
2. 前提：价格回到快速 EMA 附近，RSI 从高位回落但未跌破中轴。
3. 触发：随后一根 K 线收盘重新离开该 EMA，且成交量高于最近 N 根均值。

## 7. 止损

可定义：

- 固定百分比
- 结构止损
- ATR
- 其他规则

填写说明：止损回答“判断错了在哪里认错”。先有止损距离，才能算仓位。写清：

- 止损放在什么位置、何时移动、何时不移动
- 位置写法：**结构**或 **ATR** 并列，选定一种主写法，不要盘中改口径
- 以哪一根 K 线的收盘或最低/最高价为准
- 止损单用止损市价还是止损限价、是否只减仓
- 触发看**最新价**还是**标记价**；预估强平须远于该止损（用若干 ATR 或结构距离作缓冲，自己写数字，本模板不颁布标准倍数）
- 触发后是否立即市价离场；止损限价未成交时下一步是什么

永续合约的止损还需考虑滑点、瞬间插针和强平价。最新价止损未成交时，标记价仍可能先触发强平。止损过近会提高被扫出的频率；过远会迫使仓位变得很小，或在同等仓位下放大单笔亏损。详见 [execution.md](./execution.md)、[position-sizing.md](./position-sizing.md)。

## 8. 止盈

可定义：

- 固定 R
- 结构目标
- 分批止盈
- 移动止盈

填写说明：止盈是离场规则的一部分，不是“看情况”。写清第一目标、是否分批、剩余仓位如何移动。如果使用移动止盈，写清启动条件和回撤幅度。止盈规则应能与第 11 节的盈亏比一起检查。

## 9. 仓位

定义：

- 单笔最大风险
- 最大仓位
- 最大连续亏损限制

填写说明：仓位由“账户允许亏多少”和“止损有多远”反推。杠杆只决定保证金占用，不决定风险大小。详见 [position-sizing.md](./position-sizing.md)。建议同时写：

- 单笔风险占账户权益的上限（1R 的金额）
- 同方向、同品种的总风险上限
- **热度上限**：当前所有未平仓计划风险之和（按 R 或权益百分比）；碰到时先平、先减、或禁止开新仓，动作事先写死
- **相关品种**：与 BTC 同向的山寨是否计入同一风险因子；换交易对不是自动分散
- 来回成本对照 1R（手续费、资金费、滑点），见 [cost-vs-r.md](./cost-vs-r.md)
- 达到连续亏损或日亏损限制后是否停止开新仓
- 盈利加仓须重算总热度；摊平仍视为反模式

热度细则见 [risk-management.md](./risk-management.md)。本模板不颁布标准仓位百分比或推荐杠杆。

## 10. 禁止交易条件

例如：

- 流动性异常
- 极端波动
- 数据异常
- 连续亏损达到限制

填写说明：这是系统的刹车，不是可选项。建议按来源分类：

- 市场：点差明显变宽、成交量枯竭、资金费率或持仓量数据缺失
- **事件 / 周末**：重大公布前后、周末流动性变薄、假期盘口异常——是否禁止开新仓，事先写死
- **连续强平**：盘口一跳数个点、连锁平仓进行中，不套用平时的量价读法
- 账户：当日亏损达到上限、连续亏损达到上限、回撤超过预设、热度已到上限
- 执行：无法可靠挂止损、即将结算或数据中断
- **执行偏差**：错过触发后市价追、浮亏把止损往远处拖、为回本加仓、因共振加杠杆——对应动作见 [risk-management.md](./risk-management.md)
- 主观：规则读起来需要“临场解释”时，视为条件不成立

禁止条件触发后的动作也要写清：空仓、只平不开、或缩小到预先写好的观察模式。不要写“灵活处理”。

## 11. 回测

至少记录：

- 胜率
- 盈亏比
- Profit Factor
- 最大回撤
- 总交易次数
- 连续亏损
- 平均盈利
- 平均亏损
- 交易成本
- 滑点

填写说明：不要只填胜率。样本过少时，其余数字也不宜当作稳定特征。成本与滑点必须计入，否则永续合约的高频或短周期规则容易被高估。指标定义、统计口径和常见误区见 [backtest.md](./backtest.md)。成本如何对照 1R，见 [cost-vs-r.md](./cost-vs-r.md)。

还必须写清检验方式，而不是只在同一段历史上调到好看：

- **样本外**：规则写完（或调完）之后才看的区间，单独报告
- **滚动前进**：先在 A 段调整，B 段只验证、不许再调；再向前滚时，新的未见区间才是下一轮验证段
- **成交假设**：收盘碰到即成交，会漏掉盘中止损；止损滑点不优于入场
- **成本对照 R**：手续费、资金费、滑点已换成多少 R，期望是否已减去这一项

回测结果只能描述“这套规则在这段样本里的表现”，不能外推为未来收益。历史观察不能代表未来结果。

## 12. 复盘

记录：

- 是否遵守规则
- 是否存在主观干预
- 是否出现异常市场环境

填写说明：复盘先分“执行质量”和“规则质量”。先问有没有按规则做，再问规则要不要改。一次亏损或一次盈利都不够用来改系统。建议附带：当时识别的环境、方向、前提、触发、计划中的止损止盈、实际仓位、实际离场、以及是否触发禁止条件。

日志至少再补这些字段，否则第 6、7、9 节无法核对：

- 订单类型（开仓 / 止损 / 止盈）
- 计划价与成交价、滑点
- 持有期间收过或付过几次资金费、金额
- 这笔前后的账户热度
- **是否违规**（追价、改周期、拖止损、为回本加仓等）；违规笔不进规则成绩

## 补充：离场清单（归属第 7、8、10 节，不新增编号）

写系统时至少能回答下面四类离场，避免只写“止盈止损”：

| 类型 | 典型问题 | 写在哪一节 |
|---|---|---|
| 止损离场 | 价格触及认错位置 | 7 |
| 止盈离场 | 价格到达目标或移动止盈 | 8 |
| 时间离场 | 持仓超过预定根数仍无进展 | 8 或 10 |
| 规则失效离场 | 环境翻转、数据异常、禁止条件出现 | 10 |

## 补充：最小可回测标准（不新增编号）

一套填写完整的模板，应能让另一个人按同一规则在历史数据上数出交易次数。如果做不到，先改第 4–8 节的措辞，不要先调参数。第 3 节的周期对、第 6 节的未成交算法、第 7 节的止损价格口径，缺一项也数不出来。
