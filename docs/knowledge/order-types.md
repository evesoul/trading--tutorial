# 订单类型与成交（Order Types）

面向教学的机制说明。读完应能解释：规则如何变成一笔可能成交、也可能不成交的单。

本文件讲**订单与成交结果**，不讲买卖时机，不写具体交易所按钮位置、API 或刷量。屏幕上的价格与保证金数字见 [perp-screen.md](./perp-screen.md)。永续强平机制见 [perpetual-futures.md](./perpetual-futures.md)。

名称因交易所而异。课文写「市价 / 限价 / 止损市价」这类通用名即可。

---

## 1. 它是什么

**订单（Order）**是把交易意图交给撮合引擎的指令：在什么价、以什么方式、买还是卖、开仓还是减仓。

订单不是观察工具，也不是「方向正确」的证明。挂出去之后，结果可能是：全部成交、部分成交、触发了但没成交、被自己或系统撤销、或在成交前先被强平。

教学要分清三层：

| 层 | 含义 |
|---|---|
| 计划 | 规则里写的入场价、止损价 |
| 订单 | 真正送到撮合的指令类型与条件 |
| 成交 | 实际成交价、数量、手续费与滑点 |

计划价不等于成交价。

---

## 2. 它解决什么

学习者需要把「我认错就走」写成**一笔可能成交的单**，而不是只在图上画一条线。

本文件解决：

1. 市价、限价、止损市价、止损限价各承诺什么、各放弃什么。
2. **只减仓（Reduce-Only）**、**只做 maker（Post-Only）**避免哪类意外。
3. **有效期（Time in Force）**用白话怎么记。
4. 永续上：最新价止损单与标记价强平不是同一件事。
5. 部分成交、触发后没成交，系统要事先写怎么算。
6. 薄盘里，止损单的行为接近市价扫货。

不解决：推荐哪家交易所、怎么点哪个按钮、如何用 API 下单。

---

## 3. 常见订单

### 市价单（Market Order）

立刻按对手盘能成交的价格吃单（taker）。成交速度快，**滑点由当时盘口厚度决定**，尤其在薄盘或急跌急涨时，成交价可以远离你下单时看到的最新价。

市价解决「必须成交」；它不保证价格。

### 限价单（Limit Order）

你出的价格（或更好）。买单不会高于该价成交，卖单不会低于该价成交（常规撮合）。**可能一直不成交**。未成交部分继续挂在簿上，直到成交、撤销或过期。

限价解决「价格边界」；它不保证成交。

### 止损市价（Stop-Market / Stop Order）

价格触发条件之后，**变成市价单**去吃对手盘。触发价不是保证成交价。触发后的滑点与市价单相同。

常用于认错离场：条件到了，优先成交，而不是优先价格。

### 止损限价（Stop-Limit）

价格触发条件之后，**变成限价单**。触发了仍可能不成交：行情穿过限价、簿上没有对手、或只成交一部分。

止损限价保住价格边界，但在急变里可能**穿价后仍留着仓位**。教学必须把「触发 ≠ 成交」写进系统假设。

| 类型 | 承诺 | 放弃 |
|---|---|---|
| 市价 | 尽快成交 | 成交价 |
| 限价 | 价格边界 | 成交本身 |
| 止损市价 | 触发后尽快成交 | 成交价 |
| 止损限价 | 触发后仍守价格边界 | 触发后的成交本身 |

---

## 4. 只减仓与只做 maker

### 只减仓（Reduce-Only）

这笔单最多把已有仓位减小，不会在平仓方向上**开出反向新仓**。

解决什么：平仓单或止损单若写成普通单，在仓位已变、或部分成交之后，余量可能变成反向开仓。只减仓把这类意外挡住。

教学默认：认错离场、减仓、止损，优先用只减仓。它不保证成交，也不降低强平风险。

### 只做 maker（Post-Only）

只挂到订单簿当 maker。若下单瞬间就会与对手成交（变成 taker），交易所通常**撤单或不接受**，而不是让你吃单。

解决什么：不想付 taker 费、不想吃单冲击时，用它保持挂单身份。代价是：该成交时不成交。

不要把只做 maker 写成「更专业所以更安全」。它只是成交角色约束。

---

## 5. 有效期（白话）

名称因所而异，教学记行为：

| 缩写 | 英文 | 白话 |
|---|---|---|
| GTC | Good Till Cancel | 一直挂着，直到成交或你撤 |
| IOC | Immediate Or Cancel | 能立刻成交的部分成交，其余立刻取消 |
| FOK | Fill Or Kill | 不能全部立刻成交，整笔取消 |

IOC / FOK 常见于市价或急于知道「现在有没有对手」的限价。GTC 是挂单等待的默认直觉。

有效期不改变永续的强平规则。挂着 GTC 止损，账户仍可能先被强平。

---

## 6. 最新价止损单 vs 标记价强平

永续屏幕上至少两套价格在起作用，见 [perp-screen.md](./perp-screen.md)：

- **最新价（Last Price）**：K 线与许多止损单的触发价源（以交易所设置为准）。
- **标记价（Mark Price）**：未实现盈亏与**强平估算**用的参考价。

要点：

1. 你在最新价上挂的止损，触发看的是最新价（或你选定的价源）。
2. 强平看的是标记价与维持保证金，**不等待你的止损单成交**。
3. 因此：**止损尚未成交，也可能先被强平。** 高杠杆、止损挂得比强平线更远时，尤其容易发生。
4. 部分交易所允许止损按标记价触发。课文必须写明「这份单看的是哪一个价」，不要假设全市场同一设置。

只在最新价挂很近的限价止损、同时又用很高的杠杆，是常见反例：插针扫到最新价时限价可能不成交；标记价先碰到强平线时，计划中的止损来不及工作。本站不鼓励高杠杆。

## 7. 部分成交、触发后没成交

系统（阶段 3）必须事先写清，而不是盘中再发明：

| 结果 | 教学上要回答的问题 |
|---|---|
| 部分成交 | 已成交部分算入场吗？剩余挂单保留、改价还是撤销？止损与仓位按已成交数量重算吗？ |
| 触发后没成交 | 止损限价触发了但没吃到：视为仍持有，还是视为规则未执行？ |
| 开仓未成交 | 条件触发但限价没成交：视为**未入场**，还是追价？本库教学倾向：未成交视为未入场，除非系统另写「允许一次追价」。 |
| 止损未成交且仍持仓 | 仓位还在，计划风险已经失效，须有备用动作（例如改市价只减仓），不能假装止损还在。 |

「追价」会把滑点从计划外再加一截。知识库只要求把分支写明，不颁布必须追或必须放弃。

回测若把收盘价当成已经成交，会高估限价与止损限价的成交率。盘中路径与止损被扫，见 [kline.md](./indicators/kline.md)。

## 8. 薄盘里，止损 ≈ 市价扫货

流动性差、跳价、或清算瀑布进行时（见 [liquidation-cascade.md](./indicators/liquidation-cascade.md)）：

- 止损市价触发后，对手档可能已经空了，成交价可以远离触发价。
- 止损限价更可能触发而不成交。
- 此时把「止损单」理解成**带条件的市价扫货**，比理解成「会在那根线上成交」更接近实盘。

这不是鼓励把止损取消，而是说明：薄盘里计划中的亏损金额经常被滑点放大。历史成交不能代表未来相同的滑点。

---

## 9. 常见误读

1. **图上画了止损线 = 已经有一笔会成交的单。** 没送到撮合、或类型选错，线只是线。
2. **止损限价更安全。** 它更守价格，不更保证离场。
3. **最新价碰到止损价 = 已经平掉。** 可能部分成交、完全没成交，或先被标记价强平。
4. **全仓 / 高杠杆可以靠更近的止损活命。** 止损与强平是两套触发；强平可以更早。本站不鼓励高杠杆。
5. **只减仓可以防止强平。** 它只防止平仓单开出新仓。
6. **只做 maker 就能省手续费。** 不成交时，省下的是一笔没发生的交易，不是一笔更赚的交易。
7. **部分成交可以忽略。** 名义、保证金、止损距离都已变，不重算等于改规则。
8. **具体某交易所的按钮名称 = 通用知识。** 名称因所而异，课文用行为描述。
